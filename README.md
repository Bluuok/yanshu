## 当前统一决策

1. **第一阶段材料实验试点，两条并列业务线**：可核验、可编辑且尽量少人工修改的论文初稿；可持续更新和提醒的动态实验规划。
2. **结果导向**：导师的 12 步是参考方法库，不强迫任务走满；不把审稿意见和作者全过程历史记录当作必需样本。
3. **真实证据与隐私优先**：A/B/C 资料分级；未经授权数据不外传。不存在原始实验数据时不伪造结果。
4. **首轮评测务实**：目前的 12 篇为候选论文，不等于已下载、核验过 12 套原始数据；评分维度/权重是待导师校准的建议，不宣称能预测论文发表。
5. **优先复用、只选一套主平台**：OpenScience 为**需要实际体验/源码验证的首选候选**，不是已经确认完成二开。OpenResearch 只作为计算实验的可选工具，腾讯 Hyra 2.0/Yunque 用于借鉴研究任务分层和监督机制；后备底座 DeerFlow 2.1 仅在主候选实测不通过时再评估。详见 [技术调研](技术调研.md)。
6. **六阶段长期目标保留**：自动仿真、设备操作、受控 RSI 和个人科研 Bot 不强行纳入本期交付。

## 研发技术调研入口

在正式二开前，先看 **[技术调研](技术调研.md)** 的**两类清单**：①能通过 API、SDK、MCP、Skill 或受限 CLI 直接接入的候选工具与服务；②只能借鉴架构、算法或评测方法的项目。特殊项目（如 OpenResearch）须实际验证接口和重复调度风险。各候选严格区分「待调研／已实测／已采用」，避免维护多个 Agent 主框架。

## 接下来怎么推进

**先**对 [测试论文](测试论文.md) 的一套材料实验论文做文件级验收 → **再**按 [选型与体验](选型与体验.md) 用该案例体验 OpenScience，并用 [论文评分](论文评分.md) 保留初稿质量/引用/计算的证据 → **然后**验证实际扩展接口、实验规划、权限和任务恢复 → **最后**决定是否正式 Fork 作为唯一主底座。
