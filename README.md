## 权威性与工作顺序

1. **长期方向**：项目最高原则 + 《建设总纲与架构》。
2. **首月已确认需求**：《首月 V1 目标与计划》及《第一阶段实施规范》。连续 **30 自然日**、Day 24–30 七天测试；首月采购上限 **4,000 元**，属于第一阶段约 **12,000 元**规划的一部分。双路线并列，首月 C 级是**软件目标**，不是科研深度 C4，也不等于正式科研质量通过。
3. **科研规则**：两份专项评分及科研深度方法；**研究者/导师未确认的科学阈值不得自动生效**，原始数据必须真实、可复算、授权可追溯。
4. **技术实现顺序**：先按 [V1 开发实施计划](docs/02-产品与实施/00-V1开发实施计划.md) 和 [F01–F15 功能候选方案](docs/02-产品与实施/00-V1实施总方案.md) 明确依赖、产物和按缺口考虑的第三方能力；通过受控实测与许可核查后，在**现有** [选型与验证](docs/04-技术选型与开发/01-选型与验证.md) 登记获批准的技术决定，再将版本、源码路径、接口、人日和回退方案补入**现有开发实施计划**冻结执行。不另建第二份技术决定入口或日程主表。OpenScience 的 Fork/SDK、前端二开和专业工具仍未正式选型；不得把候选写成已部署。
5. **历史资料**：供查证旧结论与来源，不能覆盖已确认的新决策。
