# 研枢 V1 实施总方案

版本：2026-11-14。状态：**可供开发评审的实施基线，尚非已经实现或通过实机验证的软件**。

**用途**：研发人员、项目负责人、研究者和验收者只需先读本文件，就能判断每项首月功能的用户结果、实现方法、修改范围、异常与风险、人工决定、测试与验收。细节下沉到现有规范，不在正文重复数据库字段和 Agent 原理。

## 1. 已确认的交付边界

| 项目 | 已确认要求 | 不在首月承诺 |
|---|---|---|
| 两条主线 | 真实材料数据到论文主要章节初稿；科学实验设计、动态反馈与重排 | 投稿录用保证、真实仪器操控、工业仿真自动操作 |
| 时间与人力 | 连续 30 个自然日；两名能力相近的研发；Day 24–30 **完整七天**做试用、回归及修复 | 为赶进度取消测试周 |
| 部署与产品 | Ubuntu 实验室工作站运行，Windows 经授权浏览器使用；改造 OpenScience 原有工作台；交互式甘特图 | Windows 本机独立后端、正式多租户服务 |
| 运行与数据 | OpenScience 优先作为唯一 Agent 底座；业务状态及科研证据由研枢管理；本地 SQLite | 第二套 Agent Harness、未授权材料外发 |
| 成果与预算 | 结构完整、有证据的论文初稿；可编辑 DOCX/LaTeX；至少两种期刊配置测试；科研规划与应用运行时提醒；首月采购上限 ¥4,000 | 科学评分阈值未经导师确认即声明投稿质量达标 |

**优先级不变**：以下 F01–F15 共同覆盖已确认的 MUST，SHOULD 只在 MUST 通过后开展。科研真实性、资料授权、工艺安全、人工批准、两条完整业务路径及七天测试不能被“降级方案”删除。若实测证明工期无法承受，项目负责人必须书面调整范围或交付判断；不得由研发暗改已确认目标。

**评估状态**：V1 尚未运行。本文中“采用”表示拟定实现路径，“通过”只描述未来需要观察到的结果；没有把计划写成已完成事实。

## 2. 用户实际使用的两条完整路径

**论文路径**：Windows 打开项目，选择研究问题和稿件类型，上传获授权的材料数据及文献；看到单位与缺项检查；运行计算并查看图表；为论断查看来源；生成主要章节；检查数值、引文和科学论证；补交被要求的资料、执行定点修订；保存后重开，导出 DOCX 和 LaTeX，选择并核验期刊格式。

**实验路径**：用户输入研究目标、实验方法、设备和已确认的工艺限制；看到带依赖、时间窗、资源的候选计划；在甘特图检查冲突；批准后开始使用；录入延期、失败或新实验结果；看到科学解释与下一实验建议、受影响任务的新旧版本差异；批准新版本后收到准确且不重复的运行时提醒。

两条路线复用项目、资料、状态、证据、批准和质量记录；实验的真实反馈可以作为论文输入，计划中的未来实验不能冒充已完成的实验。

## 3. 拟改模块和责任归属

当前仓库仍以文档为主，**以下模块是拟建设的职责边界，并非已经存在或已确定的源码路径**。Day 1–5 在锁定 OpenScience 版本后把名称映射成实际文件路径和接口，写入任务卡；不可因路径未定就让两个研发重复建设相同能力。

| 模块代号 | 具体负责 | 复用或改造 | 主责 |
|---|---|---|---|
| UI | 项目页、文件/任务、论文、审批、甘特图、状态与错误展示 | 改造 OpenScience SolidJS 工作台和组件 | A、B 各自维护对应业务页 |
| ACCESS | Ubuntu 对 Windows 的有认证、加密的服务入口和项目访问校验 | 新增边界层，不开放裸 Runtime API | A |
| TASK | 研枢业务任务、状态机、审批、中断核对与安全重试 | 新增 SQLite 业务层；接 OpenScience SDK/HTTP/SSE | A |
| DATA | 数据导入、只读来源、Python 分析、图表和输出清单 | 复用受控 Python 库和 OpenScience 工具 | B |
| PAPER | 文献与证据、章节写作、引文及数值复审、DOCX/LaTeX | OpenScience Research Agent 配专业 Skills，必要时成熟转换工具 | B |
| PLAN | 材料规则、实验依赖、资源、反馈、科学建议、计划版本、甘特数据、通知 | 新增明确的业务规则及计划接口，AI 仅生成候选方案 | A 主责，B 复审材料规则 |
| QUALITY | 软件与科研评测、隐藏样本、运行费用及错误报告 | 复用原生运行回执和简易本地观测，独立科学检查 | B 主责，A 负责工程观测 |

**关键接口顺序**：UI 经 ACCESS 调 TASK；TASK 发起 OpenScience；工具读取 DATA 的受限输入并写 attempt 输出；PAPER/PLAN 仅消费经检查的资料和计算结果；QUALITY 在交付前独立核验。业务批准不能被 OpenScience 的通用工具许可代替。外部运行的 sessionID、requestID、runID 与业务 task_id 分开保存。

## 4. 首月功能实施卡

每张卡按同样六问编写。其模块代号对应上一节，验收编号 T01–T15。功能责任人与模块主责相同；涉及两人联调时写明交接。

### F01 远程工作台与用户入口

- **用户可见结果**：研究者在 Windows 浏览器登录并进入研枢项目首页，看到论文、实验计划、审批、最近结果和任务状态；长任务不会只显示转圈。
- **实现方法**：Ubuntu 运行 OpenScience 与研枢服务；拟用认证与 HTTPS 网关暴露受保护的工作台，不开放裸 Runtime API；复用 OpenScience 前端并统一导航、状态和视觉样式。Day 1–5 核验现有前端可扩展点，再确定修改方式。
- **修改模块**：ACCESS、UI、TASK 的只读状态接口。A 负责接入和权限，B 负责论文页接入。
- **异常与风险**：网络断线、会话失效、证书错误、未授权直连 Runtime、跨项目误读。断线提示重试而不提交第二次科研任务；认证失败拒绝访问。
- **人工决定**：负责人批准可访问的网络范围和账号；用户明确授权敏感数据外发；前端深改比例由 G2 技术评审确定。
- **测试验收 T01**：Windows 授权用户可浏览 Ubuntu 项目并刷新后恢复任务状态；无权账号、直接访问 Runtime、会话失效的访问均被拒绝；留下请求及权限日志。

### F02 项目创建、资料导入与真实来源

- **用户可见结果**：可新建科研项目、选实验方法、上传 CSV/Excel/PDF、查看来源/单位/缺项；原始文件和清洗结果可分辨；缺资料会有可操作待办。
- **实现方法**：按字节归档原件并记录 SHA256、许可和数据版本；CSV/Excel 用显式解析规则，PDF 文献用已有阅读能力或经验证的解析器；不让模型直接把整段原始数据文本当数值分析。字段未知时生成缺项，不填假数据。
- **修改模块**：UI、DATA、TASK 的来源与缺项记录。B 负责导入、A 负责项目与状态联调。
- **异常与风险**：编码/分隔符错误、列单位不明、Excel 已损失有效数字、重复文件、上传中断、无数据使用许可；原件绝不覆盖，失败保留原因。
- **人工决定**：研究者确认字段含义、标准版本、原始数据许可和是否接受补充资料。
- **测试验收 T02**：导入一套逐文件核验的真实公开材料数据，可查来源哈希和字段；故意删除必需列或使用不明单位时只阻断相关分析并请求补资料；重复上传不改写原件。

### F03 Agent 执行、业务状态和恢复

- **用户可见结果**：用户能看到 PENDING、RUNNING、WAITING_FOR_DATA、WAITING_FOR_CONFIRM、RECONCILING、FAILED、COMPLETED 等业务状态；中断后能查任务、原产物和待处理事项。
- **实现方法**：TASK 保存业务状态、检查点、task_attempts 和 session/request/run 三类 ID；OpenScience 只管 Agent 执行。首选每 attempt 独立 project 工作区，原始数据映射成只读输入副本/挂载，输出独立；Snapshot 与 SSE 观察状态。崩溃后先核对工具副作用，再决定是否重新提交。
- **修改模块**：TASK、DATA 文件沙箱、UI 状态展示。A 负责，B 提供一个真实 Python 工具用于集成测试。
- **异常与风险**：结果已保存但回执未落库、SSE 断档、重复点击、旧任务误恢复、模型无限循环；不确定时进入 RECONCILING，不盲重跑。
- **人工决定**：对未知外部副作用的重复执行、人为重开失败任务和影响科研事实的恢复必须审批；FAILED 新建关联任务，不能直接改旧任务为成功。
- **测试验收 T03**：同一 session 同一 requestID 不重复接纳；SSE 断线恢复不新增 Prompt；模拟写产物后崩溃不覆盖数据；原始输入目录写入测试被系统权限拒绝，输出目录可写。

### F04 数据计算、科研制图与复算

- **用户可见结果**：用户看到带单位的计算指标、真实数据图表、样本数量、处理方法和“查看原始数据”入口；可以重新运行相同分析。
- **实现方法**：受控 Python 读取导入的数据，按研究者批准的测试方法做清洗、计算与绘图；保存源哈希、列/行定位、脚本版本、参数、运行环境和产物哈希。原件不写入；模型只负责选取授权工具和解释结果。
- **修改模块**：DATA、PAPER 的结果引用、QUALITY 的数值复算。B 负责。
- **异常与风险**：应变比例与百分数混用、消隙段误选、统计样本不对应、图表不当平滑、float64 舍入；标准不明确时标待确认，不写固定模量区间。
- **人工决定**：研究者确认材料、测试标准、拟合范围、异常样本处理和不能通过程序自动决定的科学方法。
- **测试验收 T04**：用实际材料样本复算一组可计算指标并与独立计算对照，图表点与原数据对应；注入单位错误和缺列时停止相应计算、不产生无依据结果。

### F05 文献检索、来源定位与论断证据

- **用户可见结果**：论文每个关键数值或引用论断可打开来源，看到文献页段、原文支持片段或实验数据及计算记录；不支持的论断显示待核。
- **实现方法**：优先使用 OpenScience 原生检索与合法取得的 PDF/元数据；按 claim/source/compute 的关联记录证据位置与版本；用独立检查核验引用是否真正支持对应论断。若原生检索不能定位段落，先实测补充检索组件，不同时部署整套新 Agent。
- **修改模块**：PAPER、DATA 证据关系、UI 引用定位、QUALITY。B 负责。
- **异常与风险**：只有 DOI 无全文、文献版本差、引文支持程度不足、把摘要当全文、未经许可下载；标记证据等级和限制，不自动声称支持。
- **人工决定**：研究者确认争议性来源、重要理论解释和有许可限制的全文使用。
- **测试验收 T05**：抽取至少五条有据论断可跳转到具体来源；故意插入错 DOI 或不支持论断的真实 DOI，系统能标记待核或冲突，不得凭 DOI 存在判通过。

### F06 主要章节初稿与主动补资料

- **用户可见结果**：根据选定稿件类型看到有实质内容的 Introduction、Methods、Results、Discussion、Conclusion 等适用章节；缺少关键资料时看到具体补充请求和受影响章节，不出现编造的实验结果。
- **实现方法**：由 TASK 按数据与引用准备程度调用 OpenScience Research Agent 的分章写作 Skill；章节输入只来自有版本的研究目标、计算结果和可定位文献；草稿保留引用和待核占位。补齐资料后定点继续受影响章节。
- **修改模块**：PAPER 章节流程、TASK 待办、DATA 结果引用、UI 编辑视图。B 主责，A 联调状态。
- **异常与风险**：输入覆盖不足、模型混淆假设与实测、章节间数字不一致、无依据创新主张、无限重写；对缺项分章节阻断并记录预算。
- **人工决定**：研究者确认研究问题、核心创新主张、目标期刊、是否允许使用某项解释与无法补做实验的限制。
- **测试验收 T06**：一套获授权真实数据生成可编辑主要章节，任一关键结果能反查来源；删除一个必须实验值时出现明确追问与占位、不得生成伪数值；补交后只修订受影响章节。

### F07 独立科研质量审查与定点修订

- **用户可见结果**：用户在每章看到问题位置、严重程度、证据、建议修改与复核状态；选择接受修订后能查看前后差异，而不是只看到模型自评总分。
- **实现方法**：QUALITY 对数值、单位、引用、方法与材料规则作确定性校验；独立的受限审查 Agent 只评证据支持、论证和机理性解释，不反复调用主写作上下文自我确认；有事实错误时回到 PAPER 进行定点修改，再检查对应断言。
- **修改模块**：QUALITY、PAPER、DATA 复算、UI 审查与 diff。B 负责审查，A 联调批准入口。
- **异常与风险**：审查模型误报、把真实科学争议判硬错误、模型循环改写、隐性改动已确认数据；设置有限修订次数和差异核查，未批准阈值不报“科研质量达标”。
- **人工决定**：方法学争议、创新性、失效机理解释和严重错误裁定必须由研究者或导师复核。
- **测试验收 T07**：注入错误单位、虚假引用和无证据机理，能定位问题与证据并标明是否已核实；仅改受影响段落，复核后显示差异和剩余未决项；未确认争议不得自动判科研通过。

### F08 期刊格式与双格式导出

- **用户可见结果**：用户选期刊及稿件类型，看到格式差异；可以下载重新编辑的 DOCX 和 LaTeX 初稿及核查记录。
- **实现方法**：保留一份结构化稿件作为唯一内容来源，按目标期刊公开作者指南形成可版本化规则包；优先评测 Pandoc 等轻量转换方案，分别渲染 Word 与 LaTeX。公式、图题、参考文献、交叉引用和图片通过回读核对。
- **修改模块**：PAPER 导出与期刊规则、UI 格式选择、QUALITY 导出检查。B 负责。
- **异常与风险**：不同格式丢公式、图表、引用或中文字符，期刊说明更新、转换依赖不兼容；导出失败不破坏原结构化稿，显示具体错误。
- **人工决定**：研究者选目标期刊和稿件类型；导师核准特定投稿规范，系统不宣称适配全部期刊。
- **测试验收 T08**：同一稿件在两种不同格式配置下导出 DOCX 与 LaTeX，Word 可编辑、LaTeX 文件可按实测环境检查，关键图片/公式/引用不缺失；模拟缺模板或转换失败能提示且源稿不变。

### F09 科学实验设计与材料专业规则

- **用户可见结果**：输入目标、条件和资源后，用户看到候选实验步骤、变量、必要对照、测量指标、依据及“尚需确认”的工艺条件。
- **实现方法**：OpenScience 生成可编辑实验候选方案；PLAN 调用经专家批准、带材料类别、标准版本、单位和适用范围的规则进行确定性验证。未获批准的规则参数不能作为硬约束或自动替代真实标准。
- **修改模块**：PLAN 方案与材料规则、PAPER/DATA 的方法资料、UI 候选方案。A 负责规则执行，B 核验专业示例。
- **异常与风险**：模型编造工艺时间、错误标准、缺对照、设备资源未知、强行套用固定试样冗余比例；阻断不安全的具体步骤并说明原因。
- **人工决定**：研究方向、实验安全、关键工艺参数、标准适用性、对照组与实验样本数由研究者确认。
- **测试验收 T09**：使用一套专家确认的材料规则生成包含可追踪依据的方案；注入违反工艺下限或未批准规则的候选时系统阻断相关步骤，要求人工确认而不是自动缩短时间。

### F10 任务依赖、资源排程与冲突判断

- **用户可见结果**：看到有起止时间、依赖关系、设备与人员占用的实验计划；冲突任务显示具体原因，而非随机调整日历。
- **实现方法**：PLAN 将实验步骤存成有向无环依赖关系，使用程序验证前置条件、工艺最短等待、可用时间窗、资源容量；AI 负责提出候选排程，不负责绕开硬性约束。
- **修改模块**：PLAN 排程/资源接口、UI 甘特数据、TASK 计划任务记录。A 负责。
- **异常与风险**：依赖成环、设备重复占用、缺人员日历、跨时区、资源默认无限可用；未知资源标待确认，不静默排为可行。
- **人工决定**：研究者确认真实设备时间、资源优先级与跨项目资源占用。
- **测试验收 T10**：至少 10 个任务、有跨日依赖及设备资源的计划能正确显示；注入环形依赖、同设备超容量重叠或硬工艺下限冲突，均拒绝激活并给出位置和原因。

### F11 实验反馈、科学下一步与局部重排

- **用户可见结果**：研究者录入延期、失败或新实验结果后，看到已发生事实、与假设的关系、复测/新对照等下一步候选及原计划和新计划受影响项的差异。
- **实现方法**：PLAN 先验证反馈与试样/仪器/数据来源的对应关系，再由 OpenScience 提供有证据的解释和候选行动；受控规则核查工艺、资源，按依赖后继节点局部重排。保留真实 experiment_feedback、候选 plan_versions 和 change_records。
- **修改模块**：PLAN 反馈/版本/重排、DATA 真实测量、PAPER 证据、UI 差异。A 负责计划，B 核验新结果与科学解释。
- **异常与风险**：把模拟反馈当实际、假设未证实却自动写结论、异常值乱剔、全局无关重排、旧版本失效导致提醒错发。
- **人工决定**：改变研究方向、重大实验条件和对科研解释存在争议的新增实验，应由研究者确认再生效；低风险时间调整按预授权边界执行。
- **测试验收 T11**：分别注入一次延期和一次明确标记为模拟或有来源的假设冲突结果。系统给出不同的科学建议并留证据，修改仅涉及受影响后继任务；未批准候选版本不影响现行计划。

### F12 交互式甘特图、计划版本与批准

- **用户可见结果**：能缩放、滚动、展开阶段、查看依赖与冲突，编辑时间/依赖并预览变更，批准后新版本生效；有表格替代视图。
- **实现方法**：UI 复用与 SolidJS 兼容的现成甘特图组件，绑定 PLAN 的真实版本数据和编辑事件；编辑只创建 DRAFT 候选，调用规则校验和审批，激活后再更新当前视图。具体库需 G2 以许可、性能和事件接口选定。
- **修改模块**：UI 甘特图与表格、PLAN 版本/审批、TASK 审计。A 负责，B 参与真实科研操作试用。
- **异常与风险**：静态图冒充可编辑视图、拖动跳过硬约束、版本竞态、长中文标题遮挡、性能卡顿；失败保留原计划，UI 展示错误。
- **人工决定**：研究者批准重要计划变更；负责人决定甘特图组件及是否允许特定低风险自动调整。
- **测试验收 T12**：10 个以上任务可在甘特图与表格同步查看，编辑后刷新仍保留正确版本；未批准候选不生效，资源冲突不可绕过，旧/新差异可查询，键盘与基本缩放可操作。

### F13 应用内提醒与重启后补处理

- **用户可见结果**：用户在项目中收到下一项实验、计划时间、前置条件及资源提示；延期或取消后旧提醒撤销，运行中应用重启后可补处理待办。
- **实现方法**：PLAN 保存通知事件、时间与稳定幂等键；由 Ubuntu 服务在应用运行时调度和扫描到期事项，发送前核对已生效计划版本、前置条件及送达记录。重启后查询待处理事件，不重复创建通知。
- **修改模块**：PLAN 通知、TASK 计划状态、UI 通知中心。A 负责。
- **异常与风险**：时区换算、重复发送、旧版本仍提醒、前序实验未完成、进程关闭或断网；不保证服务停机期间即时送达，恢复后补处理。
- **人工决定**：用户设置提醒时间、允许的渠道与延后方式；重大计划变更批准后才更新正式提醒。
- **测试验收 T13**：同一事件重复回调只保留一次有效提醒；候选计划被拒绝不触发通知；批准新计划后旧提醒取消；重启应用后补处理未过期待办且不重复。

### F14 人工审批、权限与安全边界

- **用户可见结果**：用户在统一待办中看到“申请执行什么、依据、将修改什么、数据会发送到哪里、有效期”，可批准、拒绝或退回修改；操作记录可查。
- **实现方法**：TASK 持久化 approval_requests/approval_decisions，绑定任务、计划版本、作用域、申请与批准人、有效期和幂等操作键。涉及 OpenScience live permission 时读取最新 Snapshot 再提交 runtime.decide；业务批准与运行时决定回执独立保存。
- **修改模块**：TASK、ACCESS、UI 审批页面、PLAN 版本激活。A 负责，B 提供科研高风险场景测试。
- **异常与风险**：旧快照、过期或重复批准、权限被越级扩大、审批成功但运行时决定失败；保持待核，不默认放行，服务端校验用户身份与范围。
- **人工决定**：研究方向、危险或关键工艺调整、敏感资料外发及无法核清的副作用必须由授权研究人员明确决定。普通低风险计算可按预授权策略自动执行，具体名单由负责人审定。
- **测试验收 T14**：对同一计划版本的有效审批只执行一次，过期、撤销、越权、旧任务版本和重复点击均不能激活候选计划；外发权限未批准时实际请求被阻断并有审计记录。

### F15 评测、故障定位与费用报告

- **用户可见结果**：项目可以查看执行状态、错误原因、成本摘要、科研问题清单和人工修改记录；测试报告分别显示软件功能、科研事实、科研质量和待专家确认项。
- **实现方法**：QUALITY 复用 OpenScience run/工具记录及本地 task/attempt/evidence 表，按必要字段做脱敏日志与模型费用台账。独立样本包评价论文八维和实验 E1–E10 候选细项，记录覆盖率与硬阻断；不用平均分掩盖错误，不默认引入 Langfuse 集群。
- **修改模块**：QUALITY、TASK 运行信息、DATA/PAPER/PLAN 证据、UI 结果页。B 主责科学评测，A 主责调用与费用统计。
- **异常与风险**：评分模型自我认可、隐藏答案泄漏、费用重复计入、监控故障影响科研、导师阈值尚未批准；未核实记录为 UNVERIFIED，不报告“质量达标”。
- **人工决定**：导师批准科研评分规则与门槛，专家裁定重大科学争议；负责人审批超预算与异常外发。
- **测试验收 T15**：对一例正常案例和注入虚构数据/错误引用/资源越权的案例分别记录 PASS、FAIL、UNVERIFIED 与硬阻断原因；可查原始证据、工具费用和人工修订时间；观测组件故障不使科研任务失效。

## 7. 异常场景、决策边界与验收方式

验收者按 T01–T15 检查，不以“演示看起来顺畅”作为通过证据。

| Gate | 必须看到的材料 | 失败处理 |
|---|---|---|
| G1/G2，Day 5 | 一套逐文件核验的授权样本；OpenScience runtime/SDK 版本及调用回执；Windows 登录访问；Python 实际读入数据、生成输出；只读输入写入拒绝；重复请求、中断及审批测试结果 | 存在未经授权外发、数据被改写或裸 Runtime 公开时不得通过 |
| G3，Day 17–23 | 论文材料到初稿、缺项追问、证据、审查、导出；实验计划依赖、资源、反馈、科学建议、版本审批、甘特图和通知 | 无法保存/恢复或缺主功能时记录阻断，不能将仅页面截图算完成 |
| G4，Day 24–30 | 两条可重复操作的真实使用路径；T01–T15 正反例日志和产物；独立科研评分覆盖率、导师状态、人工修订时间、预算及故障记录 | 实际软件功能与科研质量分别判定；出现已确认造假/越权/工艺违规不能通过科研交付 |

**软件验收**：T01–T15 的正常和异常预期都需要真实运行记录。凡已确认的 MUST 缺失，软件 V1 不通过；部分未实测不能写“通过”。科学审查可用真实材料或明确标注模拟的实验反馈，不得把模拟当实际成果。

**科研验收**：原始事实与引文支持、复算、研究深度和人工修订量单列。对论文采用现有八维候选、对实验规划采用 E1–E10 候选，记录适用性、覆盖率、严重错误和专家签署；未获导师批准的评分门槛不得作为已通过依据。

**安全验收**：凡输入可被工具改写、原文无授权外发、关键实验变更绕过人工批准或重复执行产生未核对副作用，均属于阻断项，不以总分抵消。

**UI 验收**：在 Windows 浏览器完整执行两条操作路径，观察任务状态、错误提示、甘特图版本与缩放、键盘使用、中文/英文混排和保存后刷新一致性。必要动效不能导致误操作，也不能阻止降低动效偏好的用户完成任务。
