# 数据库设计 V1

状态：Day 1 建表基线；适用于单机 SQLite，不表示服务端多租户权限已实现。

## 目标与文件

执行 [schema.sqlite.sql](schema.sqlite.sql) 可创建业务表。OpenScience 管会话、Agent 和工具运行；研枢只保存科研业务任务、外部运行的映射、来源与证据。第一周不要重建 OpenScience 的内部数据库。

建议执行命令：

~~~bash
python -m sqlite3 data/yanshu.db ".read docs/04-开发规范/schema.sqlite.sql"
~~~

若本机 Python 无 sqlite3 CLI 支持，可通过 Python sqlite3.connect 后 executescript 执行。启用每个连接的 PRAGMA foreign_keys=ON，配置 WAL、busy_timeout 和备份。建库前创建 data 目录，数据库不得提交到仓库。

## 表与关联

| 表 | 主键 | 作用 |
|---|---|---|
| projects | project_id | 项目与数据外发级别 |
| yanshu_tasks | task_id | 科研任务状态及安全检查点 |
| task_attempts | attempt_id | 一次 OpenScience 执行，含三个不同运行 ID |
| task_events | event_id | 状态变更与人工确认审计 |
| scientific_sources | source_id | 不可覆盖的来源文件、版本、SHA256 |
| compute_records | record_id | 脚本、环境、参数和计算产物 |
| compute_inputs | input_id | 单次计算引用的每个原始数据范围 |
| scientific_claims | claim_id | 论文版本中的科研论断 |
| evidence_links | link_id | 论断与原始来源或计算记录的多对多映射 |

一条论断可关联多个来源与计算记录；一次计算可引用多份文件及不同区域。PDF 使用页码、段落和原文片段定位；CSV 使用数据集版本、行标识、列名和解析规则，不直接假定每行只有单一物理意义。对解释性论断允许保留证据不足状态，不能自动改成已证实。

## 写入约束

1. 数据和输出的 project_id 必须一致。SQLite 外键只验证存在性，业务层应在同一事务内校验关联实体的 project_id，不允许跨项目引用。
2. 保存来源原始字节和 SHA256、大小、来源网址、许可和版本；目录由操作系统权限保证只读，immutable_path 本身不是安全机制。
3. compute_records 保存脚本哈希、运行环境指纹、输入参数及输出清单。输出清单每项至少含受控路径、SHA256 和内容类型；生成的新文件使用临时文件写入、校验后原子提交。
4. os_request_id 只在相同 OpenScience session 中有请求幂等意义。首次提交前持久化 session、request、实际请求摘要；收到响应后记录 run ID，不能把 202 当作已完成。
5. 在数据库事务中以 version 做比较更新，避免多次恢复或双击触发并发提交。SQLite 使用短事务 BEGIN IMMEDIATE，不能跨等待用户批准的时间长期持锁。
6. checkpoint_json 只存研枢的可验证事实，如已审核输入版本和已提交输出，不保存不可信的模型内部运行栈、密钥或全文敏感日志。

## 首周数据验收

建表后执行 PRAGMA foreign_key_check 和 PRAGMA integrity_check。测试不存在项目的来源引用必须失败，重复 attempt_no 必须失败，同一任务的两个活跃 attempt 必须失败。检查来源哈希与磁盘内容一致；计算产物应能反查输入文件、区域和脚本版本。尚未实现上述约束的服务代码不能标为已验收。

后续实验排程使用单独的 plan_tasks、plan_dependencies、resource_bookings 和 notification_events 表，并复用本模块的 project_id 与科研数据来源；第二周实现，不要将它们塞入 yanshu_tasks。
