# 任务状态与恢复规范 V1

状态：待编码的接口与状态约定。研枢任务状态不等同于 OpenScience run 状态。

## 业务状态

| 状态 | 含义 | 允许的下一步 |
|---|---|---|
| PENDING | 输入已登记，尚未下发 | RUNNING、WAITING_FOR_DATA、WAITING_FOR_CONFIRM、CANCELLED |
| RUNNING | 有正在执行或待确认的 OpenScience 尝试 | COMPLETED、WAITING_FOR_DATA、WAITING_FOR_CONFIRM、RECONCILING、FAILED、CANCELLED |
| WAITING_FOR_DATA | 缺少关键原始资料或参数 | 经研究员提交并校验后 PENDING 或 CANCELLED |
| WAITING_FOR_CONFIRM | 科学变更、外发授权或运行权限等待明确批准 | 有效批准后 RUNNING 或 PENDING；拒绝后 CANCELLED 或 FAILED |
| RECONCILING | 执行中断、网络结果不确定或副作用未核对 | 验证结果后 COMPLETED、可安全重试后 PENDING、否则 WAITING_FOR_CONFIRM 或 FAILED |
| COMPLETED | 成果已保存且完成业务要求的核验 | 终态；修订生成新任务或版本 |
| FAILED | 无法继续且留有错误记录 | 新任务或显式授权重开 |
| CANCELLED | 使用者或策略取消 | 终态 |

允许缺项任务暂停，不允许 Agent 凭空填写缺失的实验数据。只有用户实际批准的权限或科学判断才能通过人工确认接口继续；轮询不能代替审批。

## 提交与恢复流程

1. 在事务中核对任务版本及状态，写入 task_attempts 的 PREPARED 行，保存完整请求摘要、os_session_id 和 os_request_id；原始资料受控引用，不把私有全文写入日志。
2. 使用同版本 SDK 调用 OpenScience runtime.prompt，返回 202 只表示接收。保存 os_run_id，并用 SDK 的 Snapshot + SSE 事件跟踪；SSE 序列断档时重新取 Snapshot，不重新提交 Prompt。
3. 运行中遇到权限或问题，先从最新 Snapshot 确认仍有效，再调用 runtime.decide。审批凭据由研究员授予；服务进程崩溃后无法保证原授权继续有效。
4. 如出现 interrupted、网络提交不确定或工具超时，任务进入 RECONCILING。检查原 session、请求回执、任务产物、异步作业、外部系统状态，标记副作用 UNKNOWN、OBSERVED 或 VERIFIED。
5. 如果原 attempt 已成功产生完整且经核验的产物，可以完成业务任务；如果无法确认副作用，转 WAITING_FOR_CONFIRM。只有重试安全且前次尝试已终结时，增加 attempt_no，使用新的 requestID 发新尝试。
6. 通知、文件写入和外部调用使用独立的业务操作 ID。原子写文件、唯一约束和效果核验减少重复。requestID 不能保证第三方副作用只有一次。

## 并发控制与审计

使用任务 version 做条件更新，如 UPDATE yanshu_tasks SET yanshu_status=?, version=version+1 WHERE task_id=? AND version=?。更新行数不是 1 表示冲突，先重新读取。DB 事务不能跨模型调用或用户确认一直持有。每次状态变化写 task_events，包含执行者、旧状态、新状态和原因。

OpenScience 原生状态有 accepted、running、completed、failed、cancelled、interrupted。其 completed 仅表示 Agent 回合结束，科研业务必须另行检查文件、引用、计算及审批，才设置 yanshu_tasks.COMPLETED。

## 必测场景

- 同一 requestID 同一 session 的重复发送返回原回执；改变请求内容不沿用旧 ID。
- 连接断开后重建 SSE 订阅，不发生新 Prompt。
- Python 写出结果后模拟进程崩溃，发现既有产物后不重复计算或覆盖文件。
- 无法判断外部调用是否已执行时保持 RECONCILING 或等待确认。
- 未获研究员批准不能自动越过 WAITING_FOR_CONFIRM。
- 同一任务并发点击开始，至多创建一个未决 attempt。
