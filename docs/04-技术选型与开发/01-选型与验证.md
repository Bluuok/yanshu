### 3. 哪些问题不需要挡住技术选型文档

- **待导师审议**：首批期刊及稿件类型、各章科学深度、八维质量阈值、材料工艺硬约束、实验数据合法使用范围。可先设计可配置接口、准备公开测试样本，但不得填入未经确认的科研规则、宣称分数达标或将研究者未知条件变成事实。
- **待产品负责人核对**：口述“long files”是否就是 Langfuse；实际 Ubuntu 主机配置、Windows 访问方式、两名研发可投入时间。只能把未经核实部分写为“待定/风险”。
- **后置**：大规模材料 Skills 目录、复杂求解器/多租户、第二套 Agent 底座、工业仿真自动控制、设备联动与 RSI 自动改核心；不得为这些目标提前搭建首月不需要的完整系统。

### 4. 技术选型评审的最低交付与实施顺序

1. **查现有能力**：按业务目标逐项对应 OpenScience 原生实现，引用官方源码/SDK、许可证和实际版本；区分“可调用 API/库/Skill”与“仅借鉴架构”。
2. **验证关键风险**：优先实测 Ubuntu—Windows 运行、前端可扩展性与甘特图、Python 与原始数据隔离、Word/LaTeX 导出、执行/审批恢复。可以进行短小的技术试验，不视为正式业务开发完成。
3. **冻结少量必要选型**：技术选择记录组件与版本、接口、替代选项、额外依赖与费用、验证结果、开放问题；不可验证的项保持“候选/待测”，不能强行作最终决定。
4. **再形成独立《技术选型与集成方案》**：作为技术选型权威文件，并以此和产品目标共同输入《开发实施方案》（代码目录、任务拆分、工时和 Day 1–30 落地计划）。

技术选型阶段需同步评估**两人主要开发约 23 天、最后完整 7 天测试**的实际容量。若产品 MUST 的工作量超过可用人力，应向负责人提交明确风险及可复用组件/范围调整选择，不得静默降低 PR #3 的产品目标或压缩测试周。

### 1. 先作决定：只选一个主二开底座

**优先主运行底座： [OpenScience](https://github.com/synthetic-sciences/openscience)**（Synthetic Sciences，Apache-2.0；本轮优先亲自安装、体验、源码试跑）。

为什么：
- 已具备科研工作台、检索、文件与计算工具、Skills、领域子 Agent、权限确认、运行轨迹及扩展接口，最接近「科研流程聚合平台」而非单功能论文写作器。
- 支持 Windows、浏览器工作台、CLI、桌面程序；开发使用 Bun + TypeScript/Hono，前端 SolidJS/Electron，具有 JS/Python SDK、MCP 和插件机制。
- 源码许可证较清晰；应保留 LICENSE、NOTICE 及各捆绑 Skills 的上游署名、使用限制。

**重要边界：** OpenScience 官方架构说明其服务以本地单用户为主要假设，项目切换不等于多租户安全隔离。当前不应宣传它已具备研枢所需的「个人/项目/团队」服务器级权限隔离。可先在单机科研场景验证科研能力；若规划的多用户权限需要大量重构，必须重新评审是否仍适合作为主二开底座。

**不并行开发第二套 Agent Harness。** 首月坚持 OpenScience 为主线，出现阻断先实测定位并提出局部补救，安全/授权问题不得降低标准；是否 Fork 与如何改造原前端在实施方案中决定，不因旧文档写有“条件性 Fork”而预先冻结技术方式。

### 3. 体验怎么做，才能决定是否 Fork

**使用仓库 [测试论文](../03-科研质量与样本/04-测试论文与数据.md#src-15) 的同一套真实材料实验案例**（文件级验收后择一），并依据 [论文评分](../03-科研质量与样本/02-论文评分.md#src-13) 记录质量。未验收的数据仅能做候选，不能宣称已有科研质量通过。

| 测试 | 最低可观察结果 | 需要记录 |
|---|---|---|
| A. 论文任务 | 授权数据 → 检查字段/单位 → 分析与图表 → 有依据的论文部分初稿 | 真实数据准确、引文支持、人工修订点、耗时与费用 |
| B. 动态实验规划 | 真实 Methods → 计划/依赖 → 模拟延期/设备不可用 → 局部重排 | 变更前后对照、错误提醒、资源冲突、是否要求确认 |
| C. Skills | 同一任务使用不同 Skill，支持显式选取与禁用 | 触发准确性、实际依赖、安全权限、是否提升结果 |
| D. 证据与审查 | 故意插入错 DOI、数据单位错误、无依据的结论 | 是否定位到证据、漏报与误报、修复后是否恢复 |
| E. 恢复与权限 | 中断/恢复一次，限制文件和网络权限 | 不重复执行、没有越权泄漏、任务可追溯 |
| F. 研发可维护性 | 源码运行、增加一项局部科研工具、升级试验 | 与上游更新差异、接口稳定、是否需修改核心循环 |

**通过条件：** 能稳定完成 A 和 B 的最小闭环；C–E 不出现不可接受的权限/科研真实性问题；实现这些能力不需要重写多数核心运行时。若 B 必须通过研枢扩展实现，可以接受，但应评估改造范围和后续可维护性。

**不预设「模型写得好」就说明平台适合二开。** 必须固定模型、输入、预算和案例，比对「直接模型」「OpenScience 默认」「OpenScience + 候选科研工具/Skills」，报告质量与成本。材料实验最终科学质量由真实数据和专家裁决。

### 4. 如果试用通过，研枢自己的开发边界

- **保留上游：** 会话、工具框架、模型适配、Skills 加载、科研计算沙箱、前端基本工作台。
- **新增研枢插件/服务：** 项目任务卡，材料实验论文/动态规划场景，专门证据库及独立 Eval，原始材料分级与受控外部调用，实验依赖/提醒，研究者确认规则。
- **科研 Agent 角色：** A0–A7 是职责定义，可用上游 Research/worker + Skills 实现；避免一开始强制八个模型同时参与。
- **语言和技术：** 主二开与上游一致使用 TypeScript/Bun/SolidJS；独立数据计算、文献检索或评分器可由 Python 工具服务提供，通过稳定 API/MCP/进程接口调用，**不要把两套完整 Agent 框架串在一起**。
- **质量与保密：** 执行与隐藏 Eval 严格隔离；未发表敏感资料不默认上传外部模型；只在授权条件下使用云 API。
- **RSI：** 已有外部工作由另一成员开发，等接口核对后以「候选 Skill → 评测 → 审批 → 发布/回滚」集成，首期不让其自动改核心代码。
- **项目/团队协作：** 上游不提供现成的严格多租户边界；本期单机试点不将其伪装成已具备，未来必要时新增独立身份与资源隔离层。

### 5. 开始的明确顺序

1. **体验官方 OpenScience 稳定版**：Ubuntu 工作站安装并验证 Windows 客户端访问；使用自己的 API Key，拿一套公开材料实验输入完成 A/B 场景；记录真实文件和缺陷。
2. **源码试跑及扩展验证**：按 [官方架构](https://github.com/synthetic-sciences/openscience/blob/main/ARCHITECTURE.md)、[贡献说明](https://github.com/synthetic-sciences/openscience/blob/main/CONTRIBUTING.md) 使用 Bun 开发；只加一个论文检查工具/Skill。
3. **并行只研究专业对照**：data-to-paper 数值追溯；PaperOrchestra 分章生成；PaperQA2 引文准确。各输出一份最有价值可借鉴点。
4. **主仓与二开决策门**：记录是否满足安全、运行和扩展要求，明确需要改动的前端范围；Fork/插件/SDK 取舍由后续开发方案与实测决定，绝不把“已经采用 OpenScience”推断为“必须马上 Fork 内核”。
5. **第一条最小闭环（技术基线，不是 Day 30 终验）**：一套已验收材料实验数据 → 论文部分初稿 → A7 独立质量检查 → 实际修订 → 归档评测。

### 8. 新增研究：OpenResearch / 腾讯 Hyra 2.0 / Yunque / DeerFlow

> 2026-11-05 增量研究。详细分类见 [技术调研](02-第三方组件调研.md#src-18)。本节属于「候选/借鉴」，**不改变当前唯一主二开候选**；无本机实测结论。

| 候选 | 实际定位 | 研枢建议 | 禁止误判 |
|---|---|---|---|
| [OpenResearch](https://github.com/alphaXiv/OpenResearch) | Rust `orx` 实验树、Git worktree、日志和计算调度 | 与 OpenScience 自带的 Autoresearch **对照实测**；只在确有显著增益时作为受限工具服务 | 不当作第二套主 Agent Harness，也不等同真实材料实验排程 |
| [腾讯 Hyra 2.0](https://github.com/Tencent-Hunyuan/Hyra-results) | Overall / Mission / Worker 分层、分级记忆、知识沉淀与 Skills 思想 | 把「科研项目目标」「单任务状态」「执行 Agent」清晰分离；保持 A0/A7 职责 | Hyra-results 是成果/复现资源，**不是完整开源的 Hyra Agent 框架** |
| [腾讯 YunqueAgent](https://github.com/Tencent-BAC/YunqueAgent) | 开源动态路由、原子能力池、子目标摘要、主动 Supervisor | 研究任务上下文压缩、异常恢复与工具路由；必要时局部移植 | Supervisor 保障运行健壮性，**不等同 A7 科研论断独立审查** |
| [DeerFlow 2.1](https://github.com/bytedance/deer-flow) | 持久化委派、可插拔记忆、权限及可扩展 Skills | OpenScience 体验无法满足可维护扩展/任务状态时，才重启候选底座比较 | 不提前维护两套主平台 |

**首轮只做一个对照：** 同一套已验收材料实验数据，分别使用 OpenScience 原生与 OpenResearch 的实验版本/运行追溯方法，衡量计算准确性、版本恢复、成本和集成工作量。导师 12 步依然按需执行，不能为复刻腾讯层级而增加无价值的 Agent。
