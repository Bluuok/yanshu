## 研枢｜底座与第三方能力调研纲要

> **2026-11-10 当前使用口径**：本文件中的候选优先级不等于已选定/已安装。请先根据 [首月 V1 产品目标](../02-产品与实施/01-首月V1目标与计划.md#src-6) 和 [技术选型待决与验证清单](01-选型与验证.md#src-16) 核对必要能力、Ubuntu/Windows 兼容与实际接口；不存在的材料实验专业 Skill 再优先补缺，不批量引入所有通用 Skills。

> 2026-11-05｜范围与优先级规划；**非选型定稿、非部署实测记录**。详见 [建设总纲](../01-项目总览/01-建设总纲与架构.md#src-1)、[选型与体验](01-选型与验证.md#src-17)、[论文评分](../03-科研质量与样本/02-论文评分.md#src-13)、[测试论文](../03-科研质量与样本/04-测试论文与数据.md#src-15)、[报告复核](../05-研究报告与归档/03-技术复审报告归档.md#src-28)、[复审意见](../05-研究报告与归档/03-技术复审报告归档.md#src-29)。
>
> 第一阶段两条并列成果：真实材料实验数据支持的低修改量论文初稿；根据实验反馈不断重排、提醒的动态实验计划。导师 12 步是方法库，按任务需要执行，不强制逐步凑齐。

### 1. 三层边界：只留一个主 Agent Harness

- **运行层（只选一个）**：OpenScience 为**负责人选定的首月优先主底座目标**，先在 Ubuntu 实验室工作站、Windows 客户端环境完成官方版/源码实测和授权校验。遇阻断问题先记录、局部修复并升级负责人，不在首月无授权切换另一套主框架；历史候选 DeerFlow / LangGraph + Deep Agents 仅作技术参考。二开/Fork 方式仍留待开发方案。
- **能力层（可插拔）**：科研文献、PDF 解析、计算分析、论文写作、动态实验排程，通过 Skill / SDK / MCP / 受限 CLI / 独立 API 接入，尽量不修改上游核心运行代码。
- **质量与治理层（独立）**：原始事实/论断—证据链由研枢保存；运行 Trace 与成本可由 OpenScience 原生记录、受控 Langfuse/OTel 等服务提供；隐藏 Eval、专家校准、权限审批不能交给执行 Agent 自评替代。

### 2. 必须明确区分的两类项目

> **分类依据不是 GitHub Star 数或是否开源，而是能否通过公开、稳定、获授权的接口/组件将功能接入研枢主平台。**「可接入」表示**存在实际接入途径、值得开展集成测试**，不代表已经接入、即插即用或实测通过。每项记录版本、接口、部署方式、许可证、数据权限与运维成本；通过实测后方可标为「已采用」。

#### 第一类｜可实际接入研枢的第三方服务、组件和 Skills（优先投入调研）

| 优先级 | 能力 / 候选 | 可核实的接入途径 | 在研枢中的定位与限制 |
|---|---|---|---|
| **P0** | [Pandoc](https://github.com/jgm/pandoc) / [Quarto](https://github.com/quarto-dev/quarto-cli) | 标准 CLI 命令调用 | **直接接入候选（首月必需）**：路线 A 论文初稿导出为 Word (.docx) 和 LaTeX，成熟稳定且离线无依赖 |
| **P0** | [Langfuse](https://langfuse.com/docs/observability/sdk/overview) | JS/TS SDK、Python SDK、OpenTelemetry、API；可用 Cloud 或自部署 | **轻量试用候选**：首月仅用于 Agent Trace、Token/费用统计；完整自托管后置；学术论断—证据链必须由研枢关系库单独保存，不与 APM 日志混淆 |
| **P0** | [PaperQA2](https://github.com/Future-House/paper-qa) | Python 库的 `Docs`、`ask`、`agent_query`、CLI；独立 Python 服务包装后由主平台调用 | **直接接入候选**：学术文献索引、全文证据、引用问答；避免让其内部 Agent 与主 A0 同时管理完整工作流，优先窄范围 `Docs` 检索能力 |
| **P0** | [OpenAlex](https://openalex.org/) / [Crossref](https://www.crossref.org/documentation/retrieve-metadata/rest-api/) | 官方学术元数据 REST API | **直接接入候选**：发现论文、核对 DOI 和元数据；DOI 存在不等于被引用论断成立 |
| **P0** | [K-Dense Scientific Agent Skills](https://github.com/K-Dense-AI/scientific-agent-skills) | Agent Skills 格式的 `SKILL.md` 与部分脚本；挑选后按主平台的 Skill 路径加载 | **可移植 Skills 候选**：实验设计、数据分析、科学写作、引文检查、制图；先与 OpenScience 内置 Skills 去重，逐个审查源码/依赖/许可证/运行权限 |
| **P0** | 独立科学计算工具（Python/NumPy/SciPy/pandas/Matplotlib 等） | 受限 Python 运行环境或独立 API/执行器 | **直接接入候选**：真实实验数据处理、复算、图表；绝不默认修改原始数据，记录脚本和版本 |
| **P1** | [Docling](https://github.com/docling-project/docling) / [GROBID](https://github.com/kermitt2/grobid) / [MarkItDown](https://github.com/microsoft/markitdown) | Docling Python SDK / Docling Serve、GROBID REST 服务、文档转换库 | **直接接入候选**：论文 PDF、参考文献、公式表格、Office 附件；按文件类别选主解析器，首月以 Docling 为主（本地表格解析性能待实测），MinerU 暂缓 |
| **P1** | [OpenResearch](https://github.com/alphaXiv/OpenResearch) | `orx` CLI、回环本地 API / 独立运行服务（需逐项核验命令契约） | **条件性接入候选**：计算实验运行树、Git 版本、计算日志；与 OpenScience 原生实验功能 A/B，若收益有限则只借鉴；**不能引入第二个总调度 Harness** |
| **P1** | 模型 API / 官方直连通道 | 官方 API/SDK、已有七牛云 Modelink / DeepSeek 接口 | **直接接入候选**：按任务路由主模型与独立审查模型；LiteLLM 代理首月暂缓，依靠服务商控制台限额与代码熔断 |
| **P1** | Langfuse 离线 Eval + 已有测试论文案例 | Langfuse Dataset/Experiment API + 研枢独立评分执行器 | **可执行测试工具链**：对照模型/Skill/工作流版本；须保留隐藏答案隔离与人工专家校准 |

**说明：** 这一类是「可接入并可验证」，并非「承诺能零改造调用」。例如 PaperQA2 是 Python 包，OpenScience 主程序偏 TypeScript，通常需一层受限 Python 工具适配；K-Dense 的 `SKILL.md` 不保证依赖和密钥已经就绪。

#### 第二类｜架构、算法和评测方法借鉴（不直接作为研枢可插拔服务）

| 优先级 | 项目 / 研究 | 重点借鉴 | 为什么**不按直接接入**处理 |
|---|---|---|---|
| **P0** | [data-to-paper](https://github.com/Technion-Kishony-lab/data-to-paper) | 数据→代码→图表→稿件的数值可追溯与分阶段复核 | 主要是完整研究工作流，不是已核实的通用窄接口；**先拆解方法**，只有独立组件经代码/许可/实测审查通过才升级为第一类 |
| **P0** | [PaperOrchestra](https://github.com/google-research/paper-orchestra) | 原始科研材料→提纲→章节写作→LaTeX 的组织策略 | 主要是论文生成流程参考，与材料实验适配及 API 暴露仍需核实；不直接当成主平台插件 |
| **P0** | 腾讯 [Hyra 2.0](https://github.com/Tencent-Hunyuan/Hyra-results) | Overall / Mission / Worker、分层记忆、独立复审、Skills 沉淀 | 公开研究成果不等于完整可集成的科研 Agent 内核 |
| **P1** | 腾讯 [YunqueAgent](https://github.com/Tencent-BAC/YunqueAgent) | 动态任务路由、原子工具能力、上下文压缩、Supervisor 异常恢复 | 虽有开源代码，但优先研究局部实现，不再启动另一套主 Agent 运行系统；如后续验证独立组件才可升级 |
| **P1** | [PaperBench](https://github.com/openai/frontier-evals/tree/main/project/paperbench)、[AstaBench](https://github.com/allenai/asta-bench)、[SciFact](https://github.com/allenai/scifact)、[ScholarQABench](https://github.com/AkariAsai/ScholarQABench) | 细粒度 Rubric、科研检索/论断验证、自动评分器核准 | **公开基准/评测方法参考**，可以离线运行其中的测试程序，但不能当成研枢生产流程的功能 API 或材料实验成稿质量的直接替代评分 |
| **P1** | [LangGraph](https://github.com/langchain-ai/langgraph) / [Deep Agents](https://github.com/langchain-ai/deepagents) | 状态化流程、人工介入、检查点、Agent Harness | 技术上可作为直接运行框架；**当前只有 OpenScience 主二开候选**，因此暂列备选架构而非同装的第二主框架 |
| **P2** | [DeerFlow](https://github.com/bytedance/deer-flow) | 持久化执行、记忆、扩展与权限 | 只在 OpenScience 验收不通过时作为备选底座，不属于当前第三方服务集成 |

**边界规则：**
1. 可运行的软件不一定是可接入的服务；开源仓库不一定提供稳定 SDK/API/MCP/CLI。
2. **同一个项目可以升级分类**，但必须有具体已验证组件，例如 data-to-paper 中某个可独立调用的追溯函数，不能笼统说「整套都可集成」。
3. 可离线执行的 Benchmarks 属于研发评测工具，不等于给科研人员提供的生产服务。
4. 选型仍遵守 **一套主 Agent Harness + 多个能力插件/Skills/服务 + 独立 Eval**；集成要量化效果改善、成本与运维风险。

### 3. 腾讯与 OpenResearch 的新增考虑（不是直接换底座）

- **Hyra 2.0**（2026-11-02 发布）：公开描述 Overall（对齐总体目标）/Mission（负责单项研究）/Worker（具体执行），以及项目状态、分层记忆、共享知识、Skill 沉淀。公开的 [Hyra-results](https://github.com/Tencent-Hunyuan/Hyra-results) 是科研成果与部分复现代码，**不应描述为已完整开源的 Agent 运行内核**。适合参考「项目→任务→执行」职责分层；首期可用 A0 + 显式状态机，不强制加模型 Agent。
- **腾讯 Yunque DeepResearch**：官方开源 [YunqueAgent](https://github.com/Tencent-BAC/YunqueAgent) 有主协调 + 原子能力池、按子目标压缩历史、Supervisor 主动异常检测；更适合借鉴「动态工具路由、上下文压缩、异常隔离」。**Supervisor 偏运行正确性，不等同 A7 的数据/引用/方法独立审查。**
- **OpenResearch**：官方 [OpenResearch](https://github.com/alphaXiv/OpenResearch) 是本地优先科研运行工作台，Rust CLI `orx`、实验树、Git worktree 隔离、日志和计算后端，适合计算实验版本管理。**不是材料实验室的日程系统或仪器控制器**；只有实测优于 OpenScience 原生 Autoresearch，且受限 CLI/API 足够稳定，才接成非主调度工具。
- **DeerFlow 2.1**：增加可验证执行、持久化委派、可插拔记忆及扩展/鉴权；仅在 OpenScience 无法满足项目权限/状态/扩展时启用备选评审，避免两套平台一起维护。

### 4. 每一类必须记录的筛选表

| 维度 | 最低要求 |
|---|---|
| 可信来源 | 官方 README / 文档 + 具体代码或接口 + 发行版；记录更新时间与版本 |
| 复用合法性 | LICENSE、NOTICE、包含的第三方 Skills 许可、数据/模型授权；保留出处 |
| 兼容与部署 | Ubuntu 工作站和 Windows 远程访问 / Docker、Python/TypeScript/Rust、资源占用、API/MCP/CLI、是否强制云账号 |
| 可观测与回滚 | 失败原因、数据/代码/版本记录、可否恢复、能否稳定定点返工 |
| 实际效果 | 相同材料实验样例；真实数据正确率、引用支持率、错误漏报/误报、人工修订时间 |
| 成本和运维 | Token、工具 API、计算任务、存储、依赖、维护频率、升级复杂度 |
| 安全 | 文件权限、工具沙箱、数据出境/云端授权、提示注入、日志脱敏 |
| 重复建设 | 与 OpenScience 已内置能力重叠多少，是否值得新增一套服务 |

每项候选统一收敛为五种状态登记：**已核实接口 → 待本地实测 → 已采用**（若暂不满足首月或依赖过重则标注为 **暂缓** 或 **不推荐**）。未经过本地实机充分检验，一律不得标为「已采用」。

### 5. 实际调研顺序与最小试验

1. **基线**：从 [测试论文](../03-科研质量与样本/04-测试论文与数据.md#src-15) 中选 1 套已核验的真实实验数据 + 1 个模拟实验延期场景。先测直接模型与 OpenScience 原生，保存结果、成本与错误。
2. **底座能力**：官方版运行、源码开发、Skill 加载、文件与网络权限、暂停恢复。只扩一个小工具，量化改动成本。
3. **事实与检索**：PaperQA2 + 学术元数据、Docling/GROBID；用同一批论文测证据与引用。
4. **科研结果和稿件**：data-to-paper 和 PaperOrchestra 各找一个值得复用的局部机制；比较「原生」与「加工具/Skill」质量和成本。
5. **实验增强与长期架构**：OpenResearch 与原生 Autoresearch 对照；腾讯分层和监督机制做一项简化实验，不直接照抄全部架构。
6. **统一 Eval**：固定基线、导师校准评分器、验证升级没有使已正确的科研事实退步；严格隔离隐藏答案。

**交付仅三张表**：①技术候选与许可证/接口表，②相同输入的实测对照表，③首期采用/暂缓/拒绝清单。之后再冻结正式技术栈并创建代码仓。

### 6. 当前待验证的关键风险

- OpenScience 的**项目选择器不等于严格的多租户资源隔离**，不能在本期假定已经具备团队级安全边界。
- 大部分 Skills 可能只是编排提示词而非具备脚本/服务；检查实际依赖，必要时改造成窄范围工具。
- RSI 由其他成员建设，未取得明确 API/仓库/版本前不视为已集成。初期只预留「候选 Skill → Eval → 审批 → 发布/回滚」接口。
- 不为了凑齐导师 12 步或公开审稿意见而强行增加流程。

### 外部调研报告风险复核（2026-11-05）

外部 36 项候选/20 个推荐项目的详细报告提供了有价值的搜索线索，但其「前十必装、两至四周生产级、LLM 判分和版权/权限绝对保证」尚未实测证明；具体见 **[报告复核](../05-研究报告与归档/03-技术复审报告归档.md#src-28)**。其中 K-Dense 的脚本验证结构化表与 DOI 元数据，不能直接证明科学内容真实；LiteLLM 官方证实无数据库时全局预算直接失效放行；Langfuse 完整自托管资源需求高，建议轻量使用；MinerU 包含在线服务署名义务且依赖较高显存 GPU，首月暂缓；首批材料实验优先拉伸/胶接数据分析，不预设必须安装晶体材料库。不得复制报告中的明文密钥和未核对的 Compose/Provider 配置。

### 7. 2026-11-10 首月新增接入原则（优先级高于本文件旧的体验顺序）

- 负责人选择较完整 C 级交付，UI 需修改 OpenScience 前端，支持复杂可交互甘特图、视觉美化与动效；具体二开、渲染组件和 Skills 仍需版本/可维护性验证。
- 第三方能力**不存在或已有可复核的明显缺陷**时，优先挑选成熟且合法的服务/Skill/库直接做窄范围接入验证；仅在功能重叠且质量差异不确定时做系统 A/B。不得将主观“看起来弱”当实测证据。
- “Langfuse”暂为对口述 long files 的解释，**不是确认采购、部署版本或上传实验数据的授权**；先核对 OpenScience 原生可观测能力和本地 Trace 需要。参考 [可观测性与第三方能力接入规范](04-材料规则与外部接入.md#src-24)。
- 首月完整测试周为 Day 24–30，参照 [首月 V1 决定](../02-产品与实施/01-首月V1目标与计划.md#src-6)；本文件原先以 Windows/局部样例作技术调研的段落保留历史背景，**不作为新首月交付等级与部署地点的依据**。

## 内部技术复用研究清单

> **2026-11-10 适用性提示**：这里保留候选线索，不是现行安装清单。新的首月 C 级产品范围、Ubuntu/Windows 部署与 UI 改造，以 [首月 V1 目标](../02-产品与实施/01-首月V1目标与计划.md#src-6) 为准；具体采用/暂缓以 [技术选型待决清单](01-选型与验证.md#src-16) 的后续正式选型和实测为准。

> **分类以 [技术调研.md](02-第三方组件调研.md#src-18) 为准：①可通过 API / SDK / MCP / Skill / CLI 接入的候选服务；②仅供架构、算法和评分思想借鉴的项目。** 本文件保留历史调研线索，项目在此出现不等于已获得可调用接口、已集成或已完成许可审核。具体使用状态统一按「待调研→已实测→已采用」登记。

内部研发材料｜候选方案，不等同于已经完成代码审计、取得授权或实际集成。用于比较借鉴、调用、移植与自行实现，具体选型须做可运行试验。对外总纲突出平台功能；若实际复用代码，仍须按其许可证和约定保留版权、许可及必要署名，不因内部文档而省略。

| 候选 | 优先研究什么 | 如何验证及注意事项 |
|---|---|---|
| [data-to-paper](https://github.com/Technion-Kishony-lab/data-to-paper) | 数据到论文流程、数值到代码的数据链、过程回退与复审 | 选一个含表格的实验样例测试链路；检查其统计假设、依赖和材料领域适配。仓库标示 MIT，具体版本和依赖需复核。 |
| [PaperQA](https://github.com/Future-House/paper-qa) | 文献阅读、检索问答、证据组织 | 用异质材料文献测试引用位置与科学论断匹配；并非文献事实自动保证。项目元数据标示 Apache 系列，核验实际 LICENSE 和依赖。 |
| [LangGraph](https://docs.langchain.com/oss/python/langgraph/overview) | 工作流状态、检查点、条件分支和人工中断 | 做失败恢复/重放和重复通知测试；中断恢复时节点可能重新执行，外部操作需幂等。不是唯一选型。 |
| [GROBID](https://github.com/kermitt2/grobid) | 科研 PDF 元数据、章节、引文结构化解析 | 比较双栏、中文、公式和表格；对低置信结果人工或 OCR 复核。 |
| [Langfuse](https://langfuse.com/docs) | 调用追踪、成本与评测记录 | 比较本地部署及云服务；日志脱敏；敏感数据必须按授权处理。 |
| [Materials AutoLab 144](https://huggingface.co/datasets/MatMaster-DP/Materials-AutoLab-144) | 动态实验规划、状态反馈与约束测试设计 | 对照题包适用范围、数据许可和依赖；涉及实验设备操作的任务只作评测参考。 |
| [MADE](https://github.com/diffractivelabs/MADE) | 有预算限制的多轮材料发现评测 | 检查其模拟设定和许可证；不把材料发现优化表现等同于实验室排程效果。 |

执行步骤：明确每项能力及现有实现 → 阅读源码与许可/版本/依赖 → 用真实样例建立基线 → 比较调用、局部移植或改写的效果、集成成本与维护风险 → 记录出处、版本、修改及许可证义务 → 通过回归和专家评估后纳入。先针对论文数据追踪和实验计划重排各做一个纵向验证，避免一次性拼接大量组件。不要将第三方项目宣称为自研，也不要将所述候选的功能默认为实际可用。


### 2026-11-05 增量分类：主框架、可插拔能力、评测与架构参考

> 详细优先级与筛选记录集中维护于 [技术调研](02-第三方组件调研.md#src-18)，此处仅补充既有清单未覆盖的项目。所有项目为**待实测候选**。

| 分类 | 新增候选 | 值得验证的能力与边界 |
|---|---|---|
| 主底座候选 | [OpenScience](https://github.com/synthetic-sciences/openscience) | **唯一优先体验的主二开候选**：现成科研工作台、Skills、插件、MCP、工具、计算，核查本地单用户/团队权限边界。 |
| 失败时的备选 | [DeerFlow 2.1](https://github.com/bytedance/deer-flow) | 持久任务、记忆、沙箱、Skills、扩展与鉴权；只有 OpenScience 失败时才比较。 |
| Skills 生态 | [K-Dense Scientific Agent Skills](https://github.com/K-Dense-AI/scientific-agent-skills) | 重点挑实验设计、数据分析、制图、论文写作、审查；OpenScience 已含大量同源 Skills，**先去重再引入**。 |
| 实验追踪 | [OpenResearch](https://github.com/alphaXiv/OpenResearch) | 实验树、Git worktree、日志及计算后端；与 OpenScience 原生 Autoresearch 对照，不取代主运行层或真实实验计划排程。 |
| 论文写作 | [PaperOrchestra](https://github.com/google-research/paper-orchestra) | 非结构化研究材料→论文提纲/分章写稿/LaTeX 的可复用流程；其领域偏 AI/ML。 |
| 文档解析 | [Docling](https://github.com/docling-project/docling)、[MarkItDown](https://github.com/microsoft/markitdown) | 公式表格/Office/复杂 PDF 解析；与既有 GROBID 做同题对照，敏感文件优先本地处理。 |
| 公开科研评测 | [AstaBench](https://github.com/allenai/asta-bench)、[PaperBench](https://github.com/openai/frontier-evals/tree/main/project/paperbench) | 分模块基准、可复查的层次化评分；不可替代材料实验论文专属评分与导师试评。 |
| 腾讯开源与思想 | [YunqueAgent](https://github.com/Tencent-BAC/YunqueAgent)、[Hyra-results](https://github.com/Tencent-Hunyuan/Hyra-results) | Yunque 可研究执行监督/上下文/原子能力池；Hyra 2.0 借鉴项目→任务→执行分层与 Skill 沉淀；Hyra-results 不是完整运行框架。 |

原则：**一套主 Harness + 可替换工具/Skill + 独立 Eval**。上游代码许可证/依赖许可证分别核验，记录版本、实测样本、Token 费用和升级影响，不凭项目介绍认定已可用。
