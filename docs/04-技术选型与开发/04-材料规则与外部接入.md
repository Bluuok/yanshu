## 材料实验规则与科研质量检查规范 V1

版本：2026-11-06；状态：待批准的规则设计。本文中的字段是结构示意，不提供独立 JSON 文件或可直接使用的实验标准参数。

### 1. 规则数据字段

| 字段 | 用途 |
|---|---|
| rule_id、rule_version | 稳定标识、修订版本 |
| material_class、test_method | 材料类别与试验方法 |
| standard_id、standard_version | 对应 ASTM、ISO 或实验室认可方法的实际编号及版本 |
| scope | 试样几何、设备、环境、制备状态和适用条件 |
| parameter、value、unit | 需要确认的具体参数、数值及单位 |
| enforcement_level | STRICT、WARNING、REQUIRES_CONFIRM |
| approval_status、approved_by、source_reference | 是否获得研究者或专家批准、依据及适用范围 |
| on_fail | 阻断相关步骤、标记警告或等待研究者确认 |

规则配置可以采用 JSON，在实施时再由开发人员定义 JSON Schema。JSON 结构校验不能证明科学正确性。未获批准的 DRAFT 配置不能成为科研硬性规则；未知的拟合区间、备样比例和标准编号应留空而不是填常见经验值。

### 2. 规则执行

- STRICT 只适用于已确认且具证据的硬性工艺、安全或计量约束。违反时阻断对应任务，不得因截止日期压缩最低工艺时间。
- WARNING 用于建议，不阻塞无关工作。
- REQUIRES_CONFIRM 用于存在多种科学合理解释、重要研究方案修改或依据不足的情况，由研究人员确认。
- 实验依赖用 DAG 管理，检查依赖环、设备/人员冲突及工艺前置条件。发生延期只更新受影响任务并保留前后版本，不能把计划当已完成事实。

### 3. 数据工具与精度

CSV 使用显式编码、分隔符、字段类型和缺失值规则读取，必要时先保存文本表示；转换为 float64 时会有舍入，精度要求高的字段可在适用情况下用 Decimal。Excel 使用显式单元格类型读取，不能恢复源文件本身没有保存的数字精度。所有原件按字节计算 SHA256 并只读保存，解析、清洗、单位换算、统计脚本与输出产物都单独记录版本。

结构化 CSV/Excel 优先 pandas、openpyxl 或对应受控库；Docling 主要用于 PDF 和复杂文献附录。不能要求模型直接从大段原始 CSV 文本估算弹性模量。原始测量有效区间、消隙段、试样失效处理和统计口径需由实际材料与适用测试标准决定。

### 4. 独立科研质量复核

1. 对关键数值检查输入文件、单位、清洗与计算脚本，尽可能复算；无法复算时明确标注局限。
2. 引文要定位到文献中支持论断的具体位置。DOI 有效不能替代内容支持性核查。
3. 文献横向对比说明材料配比、环境、测试模式与失效条件；条件不可比时保留限制说明。
4. 图表不得未经说明平滑原始曲线或隐去不利样本；独立数据点、样本数和误差表示服从期刊及研究方案，而不是统一强制 n<10。
5. 材料机理审查结合力学结果、形貌及其他可用证据；不能把 AF 向 CF 转变当作所有胶接强度提升的必要条件。重大科学判断交材料领域专家。
6. 复审结果至少包括问题、证据位置、适用规则与版本、严重度、建议修订及人工确认状态。可自动确认的错误允许定点修复，保留版本变化。

### 5. 首月测试边界

首选 MAT-001 或 MAT-002 中实际下载后通过文件级检查的一套。MAT-002 用于验证拉伸强度、弹性模量、失效分类和制备参数关系，不能假设数据包含通用“屈服强度”。只在实测后确定可计算项。评测输入与目标论文答案隔离，避免通过文献检索直接获取答案；公开论文仍存在预训练污染风险。

### 6. 科学反馈与“下一步实验”判断（2026-11-11 增补候选）

> 来源：[研究深度调研报告](../05-研究报告与归档/01-科研深度调研报告原文.md#src-26) 第 2–4、6、9 部分。这里只规定科学事实和已确认工艺约束的正确处理，E1–E10 候选权重归 [动态实验规划评分](../03-科研质量与样本/03-实验规划评分.md#src-14)，不把未获批准的专家意见写为强制工艺常数。

#### 6.1 分清真实事实、假设、计划和模拟事件

- **真实实验事件**：试样/批次、设备、时间、关键条件、数据来源及研究者提交/核实状态；它不是可随计划版本回滚的任务建议。
- **计划与预测**：预计开始/结束、候选变量、预计结果、可能机制，只能标 `PLANNED / PROPOSED / HYPOTHESIS` 等事实类型标签，不能标为已完成实验。
- **模拟与专家设定**：可用于时间、设备冲突、异常结果的回归用例，但不进入真实论文 Results；可测试逻辑却不能声称真实科研发现。
- **科学证据**：明确数值来自何种数据源、解析/脚本版本、原始实验条件和支持何种论断。数据复算成功也不能单独证明试样来源真实。

同一计划不同版本应引用不变的实际反馈记录，不能以新计划里的 `task_state` 覆盖/删除已经发生的实验事实；未经确认的新结果需明确来源核查状态。

#### 6.2 异常反馈的科学核查链

针对“强度低于预期、变异增加或假设不符”等事件，按需：

1. 确认试样、仪器/校准、环境、单位、原始文件与记录完整性；
2. 评估样本/重复、测量误差、异常值与可用统计方法，不得为了产生预期趋势擅自删除观测；
3. 比较原假设与现有证据，列出可能的测量/制样/工艺/材料解释，不把相关性直接写成新机理；
4. 依据具体未解科学问题提出可能行动：继续已批准方案、必要复测、有区分力的新增对照、调整条件或暂停；每项注明预期回答什么、证据和代价；
5. 对已批准工艺规则、时间前置、设备与人员容量进行确定性检查，未知约束先问询而非默认安全；
6. 若涉及重要研究方向、工艺参数或风险/授权改变，生成研究者审批请求；只对受影响任务建候选新计划并保留差异与旧通知处理。

**典型错误**：从“某胶接样本强度提高”直接得出“特定化学键合机制已证实”；把金属胶接特定试样标准泛化用于所有 CFRP；无证据规定通用样本数、加载速度、材料处理时间；所有新结果都仅顺延甘特图而不检查研究假设。

#### 6.3 科学下一行动的价值：定性先于伪精确

记录候选行动的 `scientific_question / competing_explanations / expected_observation / evidence_required / resource_cost / risk / constraints / approval_state` 等**概念字段**。科研专家判断能否减少核心不确定性、实验条件是否可行、相对于重做或继续计划是否值得；没有可验证统计模型时不自动输出通用“信息增益 85 分”。

#### 6.4 外部材料案例与标准范围

2026-11-11 调研报告提供可核查的案例：Zuo *et al.* (2026), *Nature Communications*, DOI [10.1038/s41467-026-77206-8](https://doi.org/10.1038/s41467-026-77206-8)，展示条件→力学性能→对照→化学证据的区别；Takamura *et al.* (2024), *Materials*, DOI [10.3390/ma17020394](https://doi.org/10.3390/ma17020394)，讨论表观测量强度与实际界面强度的差异。**原始 Source Data/仿真程序完整性未经过研枢逐文件复核，不得标作已验证 A 类**。

具体标准应按研究对象/材料/测试构型确认。例如 ASTM D3039/D3039M 是聚合物基复合材料拉伸试验的适用规则，ASTM D1002 针对特定金属单搭接胶接比较性剪切测试；不得把这两个标准泛化成统一材料强度判定标准。ASTM 官方公开摘要不等于实验室已获授权全文。

### 7. 首月质量验收证据

除第 5 节既有 MAT-001/MAT-002 验收外，至少准备**一例**以新实验结果改变科学下一行动的真实或明确标记模拟的情境：数据/试样核查→原假设/备选解释→复测或区分性对照等建议→资源/工艺检查→重要变更审批→受影响任务版本变化。结果由材料领域专家评价，不以“排程更快”当成科学质量已达标。

检查结果保留来源/证据位置、原始事件与计划版本、适用规则、失败原因、人工决议、已解决与未解决项。测试者应分别判定科研事实错误、质量不充分与软件故障，不能用 Agent 分数掩盖安全或真实性问题。

## V1 可观测性与第三方能力接入规范

> 2026-11-10；状态：首月需求与选型门槛，**不是最终技术栈锁定或部署成功记录**。
> 名称待核对：用户口述“long files”暂按 **Langfuse** 解释。确认前不得把特定版本、云服务或采购写成已批准。

### 1. Langfuse/Trace：用于定位工程和能力问题，不替代科学评审

V1 希望查看：任务→子步骤→模型/工具/Skill 调用、耗时、失败原因、令牌/费用、输入输出版本与对应科研任务和运行尝试。先检查 OpenScience 原生的执行记录与费用信息是否已经提供；不足时再经受控 OpenTelemetry 或 Langfuse SDK 补充，尽量不双写整套事件系统。

**最低观测字段**：yanshu_task_id、attempt_id、os_session_id/os_request_id/os_run_id（已存在才填）、step_name、model/provider、tool_or_skill_id、status/error_class、started/ended、tokens、estimated_cost、input/output_sha256、trace_id、data_policy。公开给研发的 Trace 仅含最少可用上下文，不允许把科研原始明文、密钥或隐藏评测答案直接记录进去。

**独立性**：Trace 可以定位“哪个工具崩溃、哪一步花费多、是否重复调用”，但不证明文献支持论断、公式计算正确或实验方法安全。论文数值、引用、机理判断必须通过独立数据检查/证据审查和必要专家裁决。

### 2. 隐私与部署选择

- 首月先测试 Ubuntu 工作站本地或受控部署，明确日志数据是否外传、保存期限与访问者。Langfuse Cloud 或自托管要经过实际授权、兼容性与部署成本评审；**不因选择此工具就自动授权上传未发表材料**。
- 发送 Trace 前客户端脱敏；原始正文、科研数据、全量提示和工具输出默认关闭/摘要化；敏感数据用哈希或可访问的本地引用。留意 Langfuse SDK 与 server 版本兼容性，不把“有 Python/TS SDK”当成即可插入 OpenScience。
- 观测后端故障不得导致任务运行中断；需要评估异步队列、丢失上报、重启后的关联，明确哪些指标可以直接从本地记录复算。
- 首月不要求部署 Langfuse 所需的完整生产级监控集群；如引入后的基础设施成本高于观测收益，应保留 OpenScience 原生日志 + 轻量埋点的可执行退路。

官方参考：https://langfuse.com/docs/observability/sdk/overview ； https://langfuse.com/self-hosting/security/data-masking 。

### 3. 第三方能力选择规则

- **能力完全缺失**：存在成熟、授权许可明确且接口可用的服务/Skill/库时，优先直接接入并做最小冒烟测试；无需为了证明“没有原功能”而安排完整 A/B 评分。
- **现有功能明显薄弱**：先给出可复核的薄弱证据（例如实际调用失败、字段漏读、缺引用定位），确认候选能解决明确缺口，再做小范围接入测试；不能仅凭宣传说弱。
- **功能重叠且效果不明**：同一数据包/模型或可比预算条件下 A/B 测试准确性、质量、人工修订、耗时、费用和权限；有净收益才正式接入。
- **只能借鉴机制**：不能把需要运行第二套 Agent Harness 的完整项目伪装为简单 Skill；优先提炼局部算法或模块，避免维护两套调度系统。

按任务能力分类：结构化数据计算/绘图、文献及 PDF、写作/引用、文档/期刊格式、排程约束、甘特图 UI、执行 Trace。每项先查 OpenScience 内置能力、依赖版本与许可，再决定是否另接第三方。

### 4. Skill 权限、甘特图与论文格式的边界

- Skills 可以生成研究计划、期刊结构草稿、格式规则候选或甘特图数据描述；真实科学规则、持久化与版本审批由研枢负责；图形交互由真实 UI 组件承担。
- 未经确认的 Skill 输出不得直接成为材料试验标准或实验结果。具体工具所需依赖、账号、文件和网络访问须另行配置受控权限。
- 期刊格式优先使用官方指南、经验证的规则包与成熟文档转换工具；不能用一个“投稿排版 Skill”声称自动满足所有期刊。
- Skills 的启用、版本、来源许可、输入输出、授权与效果需登记，能禁用和回退；首月不追求装载数量。

### 5. Day 24–30 验收

至少演示：可从失败的论文生成任务定位到具体工具/模型步骤；能展示调用次数/耗时/费用及与任务的关联；确定性科研错误可跳转到源数据/复核记录而不是只给 Trace；敏感数据/隐藏答案不出现在对外可见观测；观测服务不可达时业务仍能运行。没有经实测的 Langfuse SDK/版本和部署方式，一律标注待验证。
